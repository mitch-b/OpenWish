# Add gift ideas from any store link - October 10, 2026

Adding a product link to a wishlist used to fill in the item only some of the
time. Amazon pages arrived compressed and were never decompressed, larger
store pages failed instead of being read, and a spoofed browser identity sent
Amazon lookups to a captcha. OpenWish now decompresses pages, reads the first
4 MB of large ones, identifies itself honestly, follows short links only to
public addresses, and reads
product structured data, Open Graph and microdata tags, and common store
markup such as Amazon's title, price, and image elements.

Links are cleaned before lookup: tracking parameters are removed, Amazon
product addresses become their canonical `/dp/` form, and text shared from a
shopping app ("Check out ... https://...") keeps its product name. When a store
blocks server lookups, the item still gets its link, store, and a name taken
from the shared text or the address, whether the name comes before or after
the link. Imports never overwrite details you
already entered. The importer names the store it is checking and explains
what it filled in. Successful lookups are cached for a short time, without
the text anyone shared with the link, and a
burst-friendly per-user limit replaces the earlier five-per-minute cap.
Amazon prices in European format, such as 1.299,99, now import at the right
amount, and primary buttons keep the OpenWish purple when hovered, focused, or
pressed instead of switching to the default blue.

The link and store are placed on the item before the lookup starts, so a
timeout, rate limit, or dropped connection never loses them, and a page's own
canonical link replaces them when the lookup succeeds. Lookups retry any
temporary store server error. The Add item button stays disabled while a link
is being imported. A bare store address is never used as an item name, and
when a shopping app shares a product name with its link, that name wins over
the app's own title. A captured image that can't load is left off the new item
instead of being saved as a broken image.

There are also new ways to add ideas:

- Paste a product link anywhere on a wishlist you can edit, outside a text
  field, and a new item opens with the details filled in. Wishlist pages now
  check your actual edit access, so people with Edit or Admin sharing get add
  and edit controls, and viewers who can't edit no longer see them.
- Quick add on the dashboard, and the new Add to a wishlist page at `/add`,
  take a link, shared text, or an idea, then let you choose a wishlist. Lists
  shared with you appear only when you can add to them, loaded in one request.
- The Add to OpenWish bookmarklet runs on the store page in your own browser,
  so it captures the name, price, picture, and description even from stores
  that block OpenWish. On pages with very long metadata it shortens the
  description and title so the address stays within server limits. Drag it to
  the bookmarks bar from the `/add` page.
- OpenWish now has a web app manifest. Once installed from the browser menu,
  it appears as a share target, so a product shared from a shopping app or
  browser lands on `/add`. On iPhone and iPad, copy and paste the link instead.

Unit tests cover link parsing and cleaning, structured data, Amazon,
Open Graph, and microdata parsing, bot checks, large pages and character sets,
retries, timeouts, redirects, caching, import merging, link seeding, capture
prefill, editable-list filtering, and the bookmarklet's length budget. The
browser journey uses
a synthetic store page to run the bookmarklet, choose a wishlist, review the
prefilled item, and save it. It also covers paste-anywhere, shared-text paste,
dashboard quick add, view-only filtering, a store page with very long
metadata, a captured image that can't load, the manifest, and desktop, mobile,
and dark-theme screenshots.
