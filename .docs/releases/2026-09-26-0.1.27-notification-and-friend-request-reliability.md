# Notification and friend-request reliability - September 26, 2026

Five focused maintenance improvements make core coordination workflows more
dependable and safer to change in the future:

1. Sending a friend request to someone you're already friends with, or who
   already has a pending request from you, now returns a clear conflict
   response instead of an unhandled server error.
2. "Mark all as read" no longer shows a false error when there is nothing
   left to mark as read (for example, after reading notifications in another
   browser tab); it now quietly confirms everything is already read and
   keeps the notification list and unread badge in sync with that state.
3. A genuine network failure while marking all notifications as read is now
   caught and reported instead of surfacing as an unhandled error.
4. Wishlist item images without a name now get a descriptive fallback
   `alt` attribute instead of an empty one, so screen readers always
   announce something meaningful.
5. New automated tests cover friend-request conflict handling and
   notification ownership rules (mark-as-read, mark-all-as-read, and
   delete), guarding these privacy-sensitive paths against regressions.

`DEVELOPING.md` also gained a short "Releasing" section documenting how
`version.txt`, `.docs/releases/`, `CHANGELOG.md`, and `releases.json` stay in
sync for future contributors.
